# Enhancement One: Software Engineering and Design
Branch: enhancement-software_design

The artifact that was selected for this enhancement is an inventory tracking app that was originally developed as part of the CS-360 mobile architecture and design course completed in June of 2026. The application was developed using Java in Android Studio using an SQLite database to store user and inventory information. In the application, the user can create an account, log in, add inventory items, update item quantities, and delete items. The original application also included SMS notification capabilities to notify users when an item's stock reaches zero. 
I selected this artifact for the first enhancement for my ePortfolio as it provided a functional application with opportunities to improve its functionality and security. The application provided an excellent opportunity to display my ability to evaluate an existing application and improve on the functionality and design. For this enhancement, I was able to examine the existing application, identify areas like input validation and security that could be improved, and then implement changes to enhance the existing application. 
As a part of this enhancement, several improvements were made to the application. One of the improvements was to input validation and error handling. The original application did little to verify that the information passed through by the user could be processed correctly by the application. I updated the account creation, login, and inventory operations to prevent invalid information from being passed through. Error handling was improved in these areas as well to ensure invalid information was met with the appropriate feedback. Another improvement that was made as part of this enhancement was fixing the plain-text password storage. I replaced this with salted PBKDF2 password hashing to improve the protection of user credentials. Additionally, I replaced the original SMS notifications with local Android notifications to better align with standard practices and allow users to receive alerts in a more intuitive manner. Finally, I improved the application's organization by applying separation of concerns by creating two dedicated helper classes. The classes PasswordHelper and NotificationHelper separate password hashing and notification responsibilities from the existing database and notification classes, making the implementation of the function cleaner and easier to maintain. 
The planned enhancements for this milestone were intended to align with course outcomes four and five. I believe both of these outcomes have been addressed through the improvements made as part of the enhancement. Course outcome four focuses on the use of well-founded and innovative techniques, skills, and tools to implement computing solutions. The improvements that were made to input validation, error handling, notification functions, and the separation of concerns demonstrate my abilities to improve an existing application and apply software development practices. Course outcome five focuses on a security mindset by exposing potential vulnerabilities, mitigating design flaws, and ensuring privacy and enhanced security of data and resources. The improvements that were made to input validation and error handling improved upon the application's reliability by anticipating invalid input and limiting exposure. The improvements that were made to password handling by replacing plaintext passwords with salted password hashing addressed a security vulnerability in the original application. 
One of the more rewarding aspects of this enhancement was revisiting an existing application and evaluating it for improvements. When the application was first created, the primary focus was implementing required functionality to satisfy assignment criteria. Without any guidance on what should change or what should be improved allowed me creative freedom and the opportunity to think critically as a software engineer. Through the enhancement, I came to understand that functionality alone is not sufficient in terms of quality. An application needs to be reliable, secure, and maintainable to better accommodate its functions and future iterations. One of the more challenging aspects of the enhancement was the organization of the improvements. It proved easy to get lost in the code and lose track of what was being implemented. This was also combined with determining how much restructuring was appropriate, establishing a balance between added complexity and improvements to maintainability. Working through these challenges helped me to better understand the importance of planning enhancements as well as working through them incrementally. Breaking down larger improvements into their smaller components and tasks made it simpler to track the changes that were being made and identify issues related to those improvements. 

# Enhancement Two: Algorithms and Data Structures
Branch: enhancement-algorithms_and_data_structures

The artifact that was selected for this enhancement is an inventory tracking app that was originally developed as part of the CS-360 mobile architecture and design course completed in June of 2026. The application was developed using Java in Android Studio using an SQLite database to store user and inventory information. In the application, the user can create an account, log in, add inventory items, update item quantities, and delete items. The original application also included SMS notification capabilities to notify users when an item's stock reaches zero.
I selected this artifact for the second enhancement as it provided an opportunity to demonstrate abilities in designing and implementing algorithms that expand on the functionality of the already existing application. While the application did accomplish its functions of allowing users to manage an inventory, I saw an opportunity to expand on the functionality and implement a forecasting system that would analyze historical change data and use that to predict when an item would run out of stock. Through this enhancement, I have demonstrated my ability to develop algorithms that process data and deliver additional functionality and value to an application's users. 
This enhancement featured several improvements to the application. One of the most important and prominent changes was that of the implementation of inventory history tracking. This required some database expansion to accommodate the recording of changes made to inventory quantities, which then allowed the application to maintain a history of inventory consumption and restocking. Utilizing this history information, I developed an algorithm that calculates the average daily consumption of an item over a period of seven days. The algorithm uses an ArrayList to process the historical records while distinguishing between consumption and restocking to prevent the additions from interfering with daily consumption calculations. Another improvement was the implementation of the forecasting algorithm that utilizes the daily consumption rate to estimate the number of days remaining before an item reaches zero quantity. To better accommodate users, I expanded the notification functionality to allow users to configure their own notification threshold for when they want to be notified with the predicted out-of-stock date. This was accomplished with a slider in the notifications page that can be set from zero to thirty days in advance. 
The work done in this enhancement was intended to align with course outcome three. I believe I have met the expectation of this outcome by developing an inventory forecasting algorithm, thereby demonstrating my ability to design and implement a computing solution using algorithmic principles and best practices to solve a problem while managing any trade-offs in design choices. The algorithms developed for this enhancement demonstrate my ability to perform calculations and use the results to solve a practical issue. The additions that were made to accommodate the data required for these algorithms demonstrates my ability to manage trade-offs in design choices to meet the project requirements. 
Through this enhancement, I gained a better understanding of the design roadmap. My initial thoughts for the algorithm turned out to not be the best fit for the existing structure. Working around what I had said I was going to do and what the existing structure allowed was very informative. It demonstrated a valuable lesson in product design and taking time to consider all aspects before developing a plan. One of the challenges I encountered was related to this lesson. I intended to use historical data to calculate the consumption rate; however, that information was not recorded in the existing database tables. When I had originally thought out my plan, I intended to add the column to the existing tables; however, that proved to be more a burden than a boon. I ended up creating a new table and integrating it into the existing application. Another challenge I encountered during this enhancement was how I would go about testing the forecast functionality. The way I implemented it was that an item had to exist for seven days before average daily consumption could be calculated. This was a design choice to ensure there was usage in place before a forecast could be made. This means that testing would need data that was at least this old. To overcome this, I made a seeding class that inserted historical records with already predicted consumption patterns. This then allowed me to verify that the calculations were being made accordingly and that forecasting notifications were operating as expected.
